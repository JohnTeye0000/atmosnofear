# Data Sources and Licensing Checklist

**Stage A status.** Items marked **[VERIFIED]** were found in a search result during Stage A; the search snippets are secondary, so confirm against the linked primary page before relying on them. Anything else is **[UNRESOLVED]**.

## Data-type labels (used in every table/column)

| Label | Meaning | Can be used as evidence of real-world accuracy? |
|---|---|---|
| `observed` | Measured by a real instrument/participant | Yes |
| `reanalysis` | Model + assimilated observations (e.g. ERA5), gridded | Only as "reanalysis", never as "observed" |
| `nwp_forecast` | Archived numerical weather prediction forecast | As a forecast input |
| `provider_estimate` | Commercial API's modelled travel time | No — it is a model output |
| `synthetic` | Generated by our code for software tests | **Never** |

## 4b. MUTra-CDMX (Mexico City proxy dataset, used for the experiments)

Retrieved 2026-10-23. Not committed to git (`data/external/` is ignored).

| Item | Details |
|---|---|
| Title | MUTra-CDMX: Multisource Urban Traffic for CDMX (archive `MUTra_CDMX_v4.0.rar`, inner folder `v4.0-rc1`) |
| Author / source | Arturo Carlos Rodriguez Roman (CENIDET). Zenodo DOI [10.5281/zenodo.21617011](https://doi.org/10.5281/zenodo.21617011) |
| File | 3,064,249 bytes; MD5 `b619f60eeca53b0b11191f7e979d2e28` matched the value listed on Zenodo |
| Coverage | 2024-11-01 to 2025-02-28, 5-minute, 20 consecutive segments (150 m to 2 km) on Insurgentes Sur, Mexico City; 691,200 rows, 8,936 reconstructed |
| Travel times | TomTom Traffic Flow, "direct provider outputs" -> labelled `provider_estimate`, not observed by us |
| Weather | Meteosource hourly historical weather, one corridor-level series -> labelled `provider_weather`; observed-style, **not a forecast** |
| Licence | Zenodo page: CC BY 4.0. **The README inside the archive says licence verification is still pending** and that users must consult provider terms (TomTom, Meteosource). Treat the redistribution status as unresolved. |
| Status | Release candidate (v4.0-rc1); one author; not independently validated |
| Reuse rule here | Download locally for research, never commit the data or derived row-level files, cite the dataset and acknowledge TomTom and Meteosource |

Measured properties of the dataset's weather: only 81 of 2,880 hours (2.8%) have 0.1 mm or more precipitation; 23 rainy days; 7 hours with 1 mm or more; maximum 2.8 mm/hour; 43.5 mm in total (Nov 34 h, Dec 16 h, Jan 10 h, Feb 21 h). This is dry-season data, so any rain-versus-dry comparison has very little power.

Processing decisions (documented in `src/atmosnofear/mutra.py`):
- Rows flagged `is_imputed` are dropped. The dataset reconstructed them partly by interpolation across gaps, which uses future values.
- Timestamps are local (America/Mexico_City, UTC-6), converted to UTC; calendar features use local time.
- 5-minute rows are aggregated to 15-minute bins by median.
- The forecast-timed weather comes from Open-Meteo's archived ECMWF `ecmwf_ifs025` forecast at the corridor centre; Open-Meteo reanalysis and the dataset's own Meteosource weather are oracle-type upper bounds.

## 6. Stage B measured findings (Open-Meteo, Kumasi 6.6885, -1.6244)

Measured on real API responses, retrieved 2026-10-23. These replace the matching [UNRESOLVED] items above.

1. **The default "forecast" series is not a forecast.** Requesting the Historical Forecast API without `models=` returned values identical to the reanalysis archive for 100% of hours (temperature and precipitation). Using it as "forecast weather" would have silently leaked reanalysis into the features. The client now refuses a forecast request without an explicit model.
2. **Explicit models give genuinely different series.** For June 2025, precipitation matched the archive in 52.5% of hours (`ecmwf_ifs025`), 44.9% (`gfs_seamless`), 31.5% (`icon_seamless`), 32.1% (`ecmwf_aifs025_single`). For the full cached range, `ecmwf_ifs025` matches reanalysis precipitation in 68.1% of hours, with a temperature MAE of 0.50 C.
3. **Chosen forecast model: `ecmwf_ifs025`**, configured in `configs/project.toml`. Model choice is a modelling decision; revisit it in Stage E rather than treating it as settled.
4. **History start.** `ecmwf_ifs025` values are null before 2024-02-03, so the cache starts there. About 23,800 hourly rows to 2026-10-22.
5. **Grid points are not Kumasi.** Reanalysis snaps to about (6.7135, -1.5896), ~3.5 km away (elevation 275 m). `ecmwf_ifs025` is a 0.25 degree grid, snapping to (6.75, -1.50), roughly 15 km away. Each row stores `grid_lat`/`grid_lon`.
6. **Remaining nulls** in the forecast series (precipitation 243 h, relative humidity 618 h, precipitation probability 2,088 h). They are never silently filled; an imputation policy is a Stage C decision. The reanalysis archive has no precipitation probability at all (100% null).
7. **Still unresolved:** whether each forecast value comes from a run issued before the valid time (`issued_time_utc` is not exposed). The forecasts are therefore treated as "forecast-like" until Open-Meteo's documentation or a test confirms the lead time.
8. **Seasonality.** Rain is concentrated in roughly June to October, with a sharp drop in November. Computed on both reanalysis and `ecmwf_ifs025`; full table, method and caveats in `research_plan.md` section 2.1. Gridded model output, not observation.

## 7. Overall limitations to disclose in any report

- Weather grid ≠ road-segment location; rain is hyper-local.
- Archived forecasts since ~2022 only → short span for seasonal analysis.
- Crowd-collected travel times are irregular, biased toward the contributor's route/time.
- Travel time on paratransit includes loading stops, so it measures *service* time, not free-flow road conditions.
- Reanalysis is not observation.
